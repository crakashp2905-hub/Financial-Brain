# Paper engine algorithm coverage

The intraday runner now accepts a set of named `StrategyRule` adapters in both live-paper and replay mode. Each adapter receives only the current symbol state, observed price, clock, and observed market context. It returns a side, stop and optional target; the common `DayEngine` handles sizing, exposure, bid/ask or assumed-spread fills, costs, exits and the ledger. An unknown name fails closed; a missing declared resource skips the signal with a reason. The replay VWAP is from completed bars only.

Before entry, the engine rejects a setup when its target reward after estimated exit spread is no greater than its estimated round-trip charges. It records projected reward and costs in the skip. This is a minimum economic hurdle, not a guarantee: a stop, early exit, partial fill or worse-than-estimated spread can still leave realised P&L below costs. The summary counts trades with positive gross P&L erased by costs, so this failure mode remains visible.

This is an **extension point, not a claim that all algorithms are paper-traded**. The currently wired intraday strategies remain ORB and GAP. The technical-rule screener, daily opportunity scanner, suggestion/swing books, momentum champion and research zoo have different horizons and data contracts. They must not be pasted into an intraday callback without preserving their original decision time, horizon, universe, sizing, costs and instrument semantics.

Before promoting another algorithm into a paper cohort:

1. Name and version the exact rule and freeze its parameters, eligible universe, input sources and clock.
2. Implement a pure adapter using only decision-time inputs; declare every required resource. Add replay/live parity and missing-resource tests.
3. Record its strategy/config identity, input coverage, skips and fills in a separate cohort. Do not overwrite an existing day/mode ledger merely to compare variants.
4. For daily, swing, F&O and options strategies, use dedicated horizon/instrument adapters and instrument-specific cash, margin, contract, expiry and cost models rather than the cash-equity intraday engine.
5. Compare prospective net results to a frozen benchmark; label replay as retrospective and keep broker order submission outside the paper engine.

The `runs` key remains `(day, mode)` within one ledger. Custom adapters therefore require a named cohort and explicit rule versions; the runner derives a distinct ledger path from the cohort and a fingerprint of the selected strategy/version manifest. Changing any rule implementation requires incrementing its declared version. This isolates different cohorts, but an identical cohort/day/mode still replaces its own prior result; prospective attestations and append-only run attempts remain future work.

The cohort fingerprint identifies the *declared* versions; it does not hash Python callable bytecode or attest the time a signal was generated. A prospective result needs a frozen git commit, configuration, source-data snapshot, broker timestamp and append-only record. Live/replay reconciliation is available for the default ledger; custom cohorts require the corresponding isolated ledger and a matching version in both modes. The evidence output now separates gross, charges, net, notional and positive-gross trades whose charges exceeded gross P&L. Capacity and turnover need position/account-level aggregation before they can be used as promotion gates.

The daily cash-equity book already has distinct swing, position, momentum, learned and ranking-v2 specifications. Scanner and swing candidates now need projected gross return above their own sized round-trip cost; names rejected on that basis are retained in `skips`. Factor books have no calibrated expected-return estimate (`expected_net=0` placeholder), so that rule is not misapplied to them. Their missing calibration remains a promotion blocker.
Closed daily-book summaries now show gross rupees, cost rupees, net rupees, entry notional and positive-gross trades erased by costs. Entry notional is **not** portfolio turnover: a portfolio-level denominator and exit turnover remain to be implemented.
The summary now also reports an explicitly approximate cumulative round-trip turnover multiple (`2 × closed entry notional / supplied starting capital`) and cost drag on starting capital. It is not annualized realised turnover: actual exit notional, changing equity and open-position turnover still need a cash/holdings ledger.

`paper/options.py` provides a separate **long-option** paper fill and cost hurdle. It uses the observed ask to buy, later observed bid to close, the exact contract token/expiry/lot size and the options charge schedule. It fails closed on crossed books, inadequate visible quantity, contract mismatches and expiry-day/after-expiry quotes. This is a pure fill contract, not yet a scheduled options strategy runner. Expiry settlement, assignment, physical delivery, short-option margin and multi-leg risk are not modelled; those trades must not be represented as completed paper P&L using this module.
`paper/options_runner.py` can replay an explicitly timestamped, versioned long-option intent against the authorized quote archive. Entry must be a later fresh quote within one minute; exit must be a fresh quote near the predeclared exit time. It records no-entry, cost/liquidity skip, no-exit and closed outcomes. The runner does not generate signals, attest that an intent existed before its quote, persist a forward cohort, or produce an expiry settlement. Thus its outputs are replay diagnostics, not prospective evidence.
`replay_cohort` rejects duplicate signal identities and reports fill coverage, outcome counts, gross P&L, charges and net P&L for the observed closes. An unclosed intent contributes to coverage and its status, **not** to invented realised P&L.

`paper/options_forward.py` adds an application-level append-only intent/outcome ledger. It requires a versioned intent to be recorded inside its entry window, permits one outcome only after the planned exit window, checks that an observed fill followed the recorded intent, and audits local SHA-256 payload integrity. The stored `recorded_at` is the host clock and the database administrator could rewrite rows and hashes; this is **not independent timestamp attestation**. External signed time, source-data retention proofs and an operational daily scheduler are still required before calling a cohort forward-attested.

`paper/options_spread.py` adds a defined-risk call/put debit-vertical entry envelope with same-expiry/type/underlying/lot checks, observed bid/ask and visible two-leg quantity. Its reported reserve is maximum economic loss before exit charges, **not verified broker margin**. It cannot be used to claim an executable exit, expiry settlement, assignment/physical-delivery handling, or short-option buying-power adequacy. Those remain separate gates and unsupported structures must fail closed.
