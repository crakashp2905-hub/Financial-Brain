**Disposition:** `EXTERNAL_BLOCKED` — this repository review is complete; the required account-, product-, and use-specific written approvals are not in the repository.

This is a technical evidence inventory, not legal advice or a rights grant. Public policy pages do not replace the exact account agreement, product schedule, exchange permission, or written clarification applicable to this account and workflow. No permission status is upgraded by this review.

## Executive findings

1. The market-data source inventory contains 17 source identities and the permissions register contains 102 source/use records (17 × six uses). All permission records remain `UNKNOWN_RIGHTS`; retrieval access, a paid subscription, and an internal archive are not treated as proof of permission for a specific use.
2. Zerodha's current [Kite Connect API terms](https://www.kite.trade/terms/) allow a private personal trading interface in general, but also say Kite live market data may not be used for virtual/mock trading apps, may not be displayed to the public, and returned API content may not be used to create permanent copies except where expressly permitted. This creates a material unresolved question for this project's live-data paper trading, replay, and archival use.
3. A Zerodha-hosted [Kite Connect forum clarification](https://kite.trade/forum/discussion/16304/written-clarification-for-self-built-kite-connect-trading-system) says personal analysis is allowed but permanent data storage and paper trading using live data are restricted. This is additional provider guidance; it is not a written, account-specific permission for this project.
4. NSE's current [Data Sharing & Usage Policy](https://betanseapi.nseindia.com/static/market-data/nse-data-policy) says a subscriber's agreement must establish intended use and how data is received, handled, transmitted, or disseminated; redistribution is only allowed when the relevant agreement allows it. It defines Market Data broadly to include streaming, historical, end-of-day, and corporate data. Its [Non-Display Usage Policy](https://nsearchives.nseindia.com/s3fs-public/inline-files/Non_Display_Policy.pdf) treats automated calculations supporting trading decisions, and internally derived data, as non-display uses. Whether those NSE terms apply directly or flow through the Kite subscription for this specific account must be confirmed with Zerodha/NSE.
5. AMFI's [Terms of Use](https://www.amfiindia.com/terms-of-use) limit site access to personal, non-commercial use and prohibit electronic storage of a significant portion of site content and derivative/public uses without permission. That does not settle the terms for every NAV endpoint, file, or AMC feed; those exact sources and intended cache must be confirmed.
6. BSE's [Self Data Feed portal](https://marketdata.bseindia.com/) describes registration/KYC, data plans, agreements, and payment. The repository does not contain such a subscription or evidence that public archive downloads permit indefinite storage, derived use, or redistribution.
7. TradingView's [Advanced Charts introduction](https://www.tradingview.com/charting-library-docs/latest/introduction/) says the free Advanced Charts implementation must be public and not private/behind a paywall; the [library's datafeed docs](https://www.tradingview.com/charting-library-docs/latest/connecting_data/datafeed-api/) say it contains no market data and requires the integrator's own source. If this remains a private personal project, confirm eligibility for that library or use [Lightweight Charts](https://www.tradingview.com/free-charting-libraries/) under its open-source terms. Chart-library access would not grant data rights.

## Owner/provider questions to close FB-0008

Send these questions to Zerodha support/compliance and, where necessary, NSE Data, BSE, AMFI, and TradingView. Keep the response and the exact applicable agreement in a controlled evidence location, then cite that reference in each affected permission object.

1. Does the current Kite Connect personal paid plan permit an individual to consume live quote and historical-candle data in a private, single-user application for personal research and paper simulation? The system records simulated orders/fills and does not submit broker orders.
2. May the owner retain minute candles, quote/depth snapshots, instrument masters, and derived feature values locally for replay, strategy evaluation, and paper-book audit? If so, what retention window, deletion rule, backup scope, and end-of-subscription obligations apply?
3. Does the prohibition on virtual/mock trading apps cover this private self-built research/paper workflow, or only apps/platforms offered to users? Request explicit written confirmation for this exact case; do not infer from a paid subscription or public API docs.
4. Can Kite data be shown only in the owner's private dashboard/TradingView datafeed? Confirm any restriction on sending data to third-party charting software, including local-only display, cached bars, screenshot/export, or sharing a hosted page.
5. For each NSE/BSE/AMFI/MoSPI/FRED source, what is permitted for automated retrieval, internal algorithmic/non-display analysis, derived data, storage/archive, and display? What agreement, subscription, attribution, or fee applies?
6. Does NSE's non-display policy apply to this account's use through a broker feed for automated decision-support and internal research, and is a separate agreement/fee or broker confirmation required?
7. Is TradingView Advanced Charts eligible for this private personal project? If not, use a personally licensed/open-source chart component; this does not alter the market-data authorization questions.
