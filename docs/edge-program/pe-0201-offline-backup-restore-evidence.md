# PE-0201 offline backup and restore evidence

The backup helper writes a versioned immutable dependency-set bundle with safe relative paths, file lengths and SHA-256 hashes. Restore verification rejects missing/invalid manifests, traversal, duplicate names, missing or changed files, and empty bundles. Tests preserve two same-named files in separate directories, copy the bundle to an isolated restore path, delete the source tree and verify the recovered bytes.

The daily paper evidence package now always includes the close archive, paper-account journal, and forward-runner journal. Its independent verifier replays the account journal, binds the journal head and sequence to the archive, checks OMS/account state and total-return reconciliation, and reproduces the report from copied inputs. The account journal cannot be omitted.

The `fb forward daily-finalize` CLI command reconstructs the account from its journal and runs close plus bundle export after validating the durable session terminal record. Owner-supplied close marks and capture time are explicit inputs. The new `fb forward daily-restore --bundle ... --destination ...` command verifies the bundle (and an optional pinned Ed25519 key) before creating a destination, refuses overwrite, copies to a separate restore tree, verifies the copy again, and returns the recovered session identity and account/runner evidence paths. It never enables physical orders or live collection.

Verification: the focused backup, daily-bundle, source-inventory, and evidence-audit suite passed (34 tests); Ruff and targeted mypy passed. Restore tests verify session identity and returned input paths, reverify the isolated copy, reject overwrite, and prove a tampered bundle fails before a destination is created. This is an artifact-restore drill using synthetic fixtures. Automatic discovery of quote archives, strategy/configuration inputs, registry/authority state, and an owner-authorized observed session restore/resume remain outstanding.
