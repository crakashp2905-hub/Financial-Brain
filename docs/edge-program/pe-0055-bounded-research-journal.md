# PE-0055 bounded-search outcome journal

The existing daily bounded random-search entry point now freezes its variant catalogue and mechanism source digest before loading outcomes. Each variant receives exactly one durable result with an explicit outcome and canonical details digest; the underlying journal is append-only and hash-chained. A run cannot close while any declared variant lacks a result. If evaluation errors, remaining variants are recorded as `ABORTED` and the original exception is re-raised. When a later run starts, it explicitly recovers prior open runs and marks unrecorded variants `ABORTED`, covering hard process stops that bypass exception handling.

The journal defaults to `data/bounded_search_journal.jsonl` and can be overridden through the `audit_path` argument. It is single-writer: callers must ensure another process is not actively using the same file when restart recovery runs. The CLI's JSON output retains the complete per-variant result and includes the audit run ID/path. The journal is separate from the optional summary JSON and is not a trial ledger, profitability claim, order path, alert path, or promotion mechanism. Any use must preserve the exact local audit file with the result artifact.

Acceptance coverage exercises interrupted-run recovery, duplicate and missing result rejection, bounded variant counts, non-finite float canonicalization, and end-to-end bounded-search recording for all frozen variants. This remains partial: full historical data/variant runs, independent replays, larger mechanism families, cross-process writer protection, and prospective paper results have not been produced.
