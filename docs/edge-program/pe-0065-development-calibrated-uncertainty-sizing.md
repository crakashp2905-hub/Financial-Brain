# PE-0065 development-calibrated uncertainty sizing

Added a development-only calibration policy for standardized forecast errors. It accepts unique, dated `DEVELOPMENT` rows only, estimates an empirical upper-quantile error multiplier, never deflates the supplied uncertainty estimate, hashes the data and protocol, and freezes the result in a durable immutable registry before the validation start. The shared signal allocator can consume that frozen policy and per-name forecast standard errors; its uncertainty haircut reduces adjusted net alpha and is recorded in the allocation result. It never increases alpha or tries to scale a position to a target profit.

The package is `PARTIAL`: only synthetic fixtures were available, and no in-house daily paper decision is yet required to resolve and apply this uncertainty policy. A real development sample, predeclared protocol review, policy identity binding in `ForwardRunConfig`, and application to order quantity in the paper runner remain necessary before this can be treated as an enforced paper-schedule control. Synthetic monotonicity tests demonstrate the component behavior, not calibration quality or trading performance.
