Those charts measure different task sets and different statuses; they are not the completion rate for this 1,378-item v3.0 checklist. `docs/edge-program/PROGRESS.md` records the underlying scopes:

| Earlier chart | What it measured | Correct interpretation |
|---|---|---|
| Unified platform tracker | 711 FB requirements | 246 implemented (34.6%); 187 partial. 433/711 (60.9%) means implemented **or partial**, not complete. |
| Chart-pattern matrix | 406 CP requirements | 378 implemented plus 9 evidenced not-applicable; 387/406 (95.3%) is a software-matrix pass rate for that module. |
| Forward-edge tracker | 152 FE requirements | 20 DONE (13.2%); 97 PARTIAL. 117/152 (77.0%) means some implementation activity, not done. |
| Unified checklist v3.0 | 1,378 FB/PA/SL requirements | 23 COMPLETE (1.67%); 51 audited (3.70%). This is the count to use for the current goal. |

Do not combine these numerators: task IDs, scope, and completion rules differ. Partial/started work can explain the older >50% charts while 23 v3.0 items currently satisfy strict evidence-backed completion.

## Audit method

`COMPLETE` means the stated acceptance criteria are met and linked to reproducible
evidence. `PARTIAL` means implementation or evidence exists but at least one stated
condition remains unmet. `NOT_STARTED` means no adequate implementation/evidence was
found. `EXTERNAL_BLOCKED` means the next required fact or approval cannot be created
inside this repository. Existing code, a green test, or a PR description alone does not
prove prospective profitability or market-data permissions.

The checklist explicitly separates in-house engineering from external data rights,
owner approvals, independent custody, and elapsed forward-market observations. Those
external requirements will remain visible as blockers; they will not be replaced with
synthetic claims. Existing local worktree changes are not treated as merged evidence.
